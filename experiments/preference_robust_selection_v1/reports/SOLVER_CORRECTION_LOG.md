# Solver correction and result provenance

## 12 October 2026

An initial implementation forwarded `mip_feasibility_tolerance` through SciPy's `milp` interface. SciPy warned that this option was not recognized by its wrapper. HiGHS sometimes returned a success status while reporting nonzero relative MIP gaps; the largest archived gap was 0.0142625. These solver outputs are preserved under `archive/pre_solver_gap_correction_20261012/` and are excluded from the corrected empirical results.

The unsupported option was removed. The solver now uses only supported options, independently verifies cardinality-row feasibility and binary integrality, retries with presolve enabled/disabled, and rejects results whose **absolute primal–dual objective gap** exceeds 1e-6 objective units (normalized utility for minimax regret/maximin; dimensionless ratio for relative robustness). Both absolute and relative MIP gaps are saved. A small objective can yield a visibly larger relative gap despite a negligible absolute gap; the acceptance gate is the absolute gap together with constraint feasibility. A reproduced earlier high-gap case returned the same objective with zero reported gap on repeated calls after removing the unsupported option. Unit tests compare small MILPs with exhaustive enumeration.

A first corrected run using a strict relative-gap threshold stopped on a relative-robust solution with a tiny numerical gap; a later run also showed that relative gap alone can be misleading when objective values are near zero. The final gate therefore uses the absolute primal–dual gap and records both measures. Any nonzero accepted absolute gap is described as numerical certification to that tolerance, not exact optimality. HiGHS also intermittently raised an internal `vector::reserve` exception on particular presolve attempts; the implementation catches that solver exception, retries supported presolve configurations, and records the successful solver result. A previous evaluation attempt was interrupted during an inefficient repeated full-table scenario filter; this did not alter inputs or policy outputs. Scenario lookup is now indexed once before repeating the same evaluation. Final status depends on the regenerated downstream diagnostics satisfying the validation gates.

The experimental candidate universe and outcome labels were not changed by the correction. No previous M1 experiment or audit directory was modified.
